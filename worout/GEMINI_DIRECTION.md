# Worout 프로젝트 방향성

## 핵심 목표

이 프로젝트는 단순한 운동 기록 앱이 아니라, 사용자가 매일 열어서 자기 삶을 관리하는 개인 생활 운영 대시보드다.

현재 만들어진 운동 기능은 전체 프로그램 안의 하나의 모듈이다. 나무 전체가 앱이라면, 현재 운동 앱은 그중 나뭇잎 하나에 해당한다.

## 전체 앱 콘셉트

앱의 목적은 "나 자신을 표현하고, 내가 편리하게 살기 위한 프로그램"이다.

남에게 보여주는 랜딩페이지가 아니라, 실제로 매일 사용하는 개인 생산성 도구에 가깝게 만들어야 한다.

## 최종 메뉴 구조

전체 앱은 다음 큰 메뉴를 가진다.

1. 홈 대시보드
2. 운동
3. 취업
4. 학업
5. 일정표
6. 세계뉴스
7. 반도체뉴스
8. 설정

## 운동 모듈

현재 구현된 운동 앱 기능은 버리지 말고, 전체 앱의 "운동" 메뉴 안으로 넣는다.

운동 메뉴 안에는 다음 하위 기능이 들어간다.

- 운동 대시보드
- 주간 운동 일정
- 운동 기록
- 식단 기록
- 수면 기록
- 진행 통계
- 운동 설정

기존 localStorage 데이터는 최대한 유지해야 한다.

## 홈 대시보드 방향

홈 화면은 하루 요약 화면이어야 한다.

포함할 내용:

- 오늘 운동 요약
- 오늘 일정
- 학업 할 일
- 취업 공고 새 소식
- 세계뉴스 주요 항목
- 반도체뉴스 주요 항목
- 마지막 업데이트 시간

## 취업 기능 방향

취업 메뉴는 공고 확인용이다.

중심 분야:

- 반도체 기업
- 방산 기업

필요 기능:

- 회사 watchlist
- 산업군 필터
- 직무 키워드 필터
- 신입/경력 필터
- 저장한 공고
- 지원 예정 / 지원 완료 상태 관리

처음에는 mock 데이터로 구현해도 된다. 다만 나중에 실제 채용 API, 회사 채용 페이지, RSS, 백엔드 크롤러로 연결할 수 있도록 `services/jobsService.js` 같은 서비스 계층을 만들어야 한다.

## 뉴스 기능 방향

뉴스는 실시간 갱신이 중요하다.

뉴스 메뉴:

- 세계뉴스
- 반도체뉴스

필요 기능:

- 새로고침 버튼
- 자동 갱신 토글
- 마지막 업데이트 시간
- 로딩 상태
- 실패 상태
- 빈 데이터 상태
- 원문 링크

처음에는 mock 데이터로 구현해도 된다. 다만 나중에 실제 뉴스 API, RSS, 백엔드 프록시와 연결할 수 있도록 `services/newsService.js` 같은 서비스 계층을 만들어야 한다.

프론트엔드에 API 키를 직접 넣으면 안 된다.

## 학업 기능 방향

학업 메뉴는 공부 관리용이다.

필요 기능:

- 과목 목록
- 공부 계획
- 오늘 할 일
- 완료 체크
- 공부 시간 기록
- 주간 학습 요약

## 일정표 기능 방향

일정표는 개인 일정 관리용이다.

필요 기능:

- 오늘 일정
- 주간 일정
- 일정 추가/수정/삭제
- 중요도
- 완료 여부

## 기술 방향

기존 React + Vite 구조를 유지한다.

권장 구조:

- `src/pages`: 큰 화면 단위
- `src/components`: 재사용 UI 컴포넌트
- `src/services`: 뉴스, 취업 공고 같은 외부 데이터 연결 계층
- `src/data`: mock 데이터
- `src/utils`: 저장, 계산, 포맷팅 유틸
- `src/hooks`: localStorage, 자동 갱신, 필터링 등 재사용 로직

## 중요한 구현 원칙

1. 기존 운동 기능을 망가뜨리지 않는다.
2. 기존 localStorage key는 가능하면 유지한다.
3. 전체 메뉴와 운동 내부 메뉴를 분리한다.
4. 뉴스와 취업 기능은 지금 mock이어도 나중에 실시간 연결이 쉽도록 만든다.
5. 앱은 화려한 홍보 페이지가 아니라 매일 쓰는 실용 도구처럼 보여야 한다.
6. 모바일에서도 사용하기 편해야 한다.
7. `npm run lint`가 통과되어야 한다.

## Gemini에게 줄 핵심 요청

현재 운동 앱을 전체 개인 생활 운영 대시보드의 "운동 모듈"로 재구성해줘.

전체 앱은 운동, 취업, 학업, 일정표, 세계뉴스, 반도체뉴스를 관리하는 개인용 프로그램이다.

뉴스와 취업 공고는 현재 mock 데이터로 시작하되, 나중에 실제 API/RSS/백엔드 프록시를 연결할 수 있도록 service layer를 분리해줘.

기존 운동 기록, 식단 기록, 수면 기록, 통계, 설정 기능은 유지하고, 전체 앱 안에서 자연스럽게 접근할 수 있게 만들어줘.
